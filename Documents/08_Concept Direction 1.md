


# Concept Direction 1

### 1. Name: **Guided Diagnosis Flow**

### 2. One-liner

A **step-by-step mobile guide** that helps tenants **assess issue urgency and document it correctly** so they can **take the right action with confidence**.

### 3. Core idea

- Structured Q&A replaces uncertainty with clear decisions
- Real-time urgency classification + immediate actions
- Guided evidence capture → one complete report

### 4. How it works

1. User selects issue type (water, mold, electrical, etc.)
2. App asks contextual questions (e.g., smell, frequency, location)
3. System assigns urgency level (monitor / report / urgent)
4. User receives clear “what to do now” instructions
5. App guides evidence capture (photo, notes, checklist)
6. Auto-generates structured message ready to send

### 5. Key screens

- Issue Selection
- Guided Questions (dynamic flow)
- Urgency Result + Actions
- Evidence Capture Checklist
- Final Report Preview

### 6. Data / inputs needed

- Issue type selection
- User answers (symptoms, frequency, context)
- Photos/videos
- Optional notes (timeline, smell, recurrence)

### 7. Risks / tradeoffs

- Over-reliance on predefined flows → edge cases may fail
- Wrong urgency classification could reduce trust
- Requires strong logic design to feel “smart” not rigid

### 8. Success signal

**We’ll know this works if…**

- Users immediately take action after diagnosis without hesitation
- Reports are sent in one message with complete info
- Users state “I know what to do now” without second-guessing

# Concept Direction 2

### 1. Name: **Living Evidence Timeline**

### 2. One-liner

A **continuous issue tracking tool** that helps tenants **build credible evidence over time** so they can **prove patterns and be taken seriously**.

### 3. Core idea

- Shift from “one report” → “ongoing case file”
- Timeline of photos, notes, and events
- Pattern detection (recurring issues = higher credibility)

### 4. How it works

1. User logs a new issue (e.g., mold corner)
2. App prompts periodic check-ins (“has it changed?”)
3. User adds photos, notes, timestamps over time
4. Timeline auto-organizes entries chronologically
5. System highlights recurrence patterns (“3 times in 2 weeks”)
6. User generates a “case report” summarizing history

### 5. Key screens

- Issue Dashboard (active cases)
- Timeline View (photos + notes over time)
- Add Entry (photo + context)
- Pattern Summary
- Export / Share Report

### 6. Data / inputs needed

- Photos (timestamped)
- User notes (context, actions taken)
- Frequency of occurrence
- Optional reminders/check-ins

### 7. Risks / tradeoffs

- Does not directly solve urgency in the moment (slower value)
- Requires repeated user engagement → risk of drop-off
- Might feel heavy for simple, one-time issues

### 8. Success signal

**We’ll know this works if…**

- Users consistently log multiple entries per issue
- Reports include time-based evidence without effort
- Users feel their issue “can’t be dismissed anymore”

# Concept Direction 3

### 1. Name: **Action Snapshot**

### 2. One-liner

A **fast capture + instant guidance tool** that helps tenants **quickly understand and act in the moment** so they can **handle issues safely without overthinking**.

### 3. Core idea

- Designed for “panic moment” (fast, minimal input)
- Snapshot → instant interpretation → action
- Prioritizes speed over completeness

### 4. How it works

1. User opens app and taps “What’s happening?”
2. Takes a photo or selects quick category
3. App instantly returns: urgency label + action (e.g., “Turn off valve”)
4. User gets 2–3 key things to check (minimal checklist)
5. Optional: expand into full report flow
6. Optional: send quick message immediately

### 5. Key screens

- Quick Capture (camera-first)
- Instant Result (urgency + action)
- Minimal Checklist
- Expand to Full Report
- Quick Send Message

### 6. Data / inputs needed

- Photo OR quick category selection
- Optional quick answers (yes/no prompts)
- Minimal context (location, symptom)

### 7. Risks / tradeoffs

- Oversimplification → may miss important nuance
- Lower quality reporting if users don’t expand
- Trust depends heavily on accuracy of instant feedback

### 8. Success signal

**We’ll know this works if…**

- Users act within seconds of opening the app
- Reduced anxiety in high-stress scenarios
- Users follow recommended safety actions immediately

---

# Concept Contrast (for decision clarity)

- **Guided Diagnosis Flow** → structured thinking (reduces uncertainty)
- **Living Evidence Timeline** → long-term credibility (reduces dismissal)
- **Action Snapshot** → instant action (reduces panic + hesitation)
